One Rust binary that renders a single status line for many coding agents and wires itself into each agent's config. Agents run `statusmaxxx render --host <agent>` with their session JSON on stdin; plugin agents do the same through a generated shim.

## Layout

```
src/
  main.rs          CLI: config (TUI, default), render, install, uninstall, status, issue
  payload.rs       stdin JSON (Claude Code shape) → Session
  git.rs           repo name, linked worktree, git dir, head, changed files
  issue.rs         issues the agent set, stored in the worktree's git dir
  segment.rs       Segment → Pieces (text + Role + url)
  render.rs        Pieces → ANSI line, or {"text","url"} JSON for plugin shims
  theme.rs         Role → color per theme
  config.rs        ~/.config/statusmaxxx/config.toml
  paths.rs         XDG config/cache dirs, binary path, atomic writes
  tui.rs           ratatui configuration UI with per-agent previews
  host/
    mod.rs         Host enum: tier, output format, detection, notes
    command.rs     statusLine-command agents: Claude, Cursor, Qwen, Droid, Copilot
    plugin.rs      shim agents: Amp, pi, OpenCode; sources in shims/
    builtin.rs     item-only agents: Codex, Gemini (segment → item id)
    instructions.rs  marked block in the agent's global instructions telling it to set its issue
    settings.rs    JSON settings editing with backup; refuses JSONC
    replaced.rs    remembers what install replaced so uninstall restores it
.github/workflows/ ci.yml (the `just check` gates) · release.yml (generated by `dist generate`)
```

## Commands

```bash
just                      # list recipes
just check                # fmt --check, clippy -D warnings, tests — same as CI
just config               # TUI from source
just run status           # any CLI command from source
just render claude        # replay the session JSON an agent last sent
just try claude           # real agent on the debug build via its settings override (claude, droid)
just sandbox claude amp   # install into a throwaway HOME, print what changed
just install              # release binary onto PATH (~/.cargo/bin)
just secrets              # gitleaks over history and uncommitted changes
just release 0.2.0        # bump, commit, tag, push; dist builds the release
```

## Quality

- Before a ship commit: `just check`. Warnings are errors.
- `render` runs on every status refresh (Claude debounces at 300 ms). It never touches the network, and git runs only when a segment needs the repository. Check the cost with `time` against a large repo when you touch it.
- Tests guard contracts: payload fields, git parsing, config overrides, settings edits that must not destroy user files, and the instruction block round trip. Load `in-house-test-audit` before adding one.

## Conventions

- No emojis anywhere. Icons are Nerd Font code points written as `\u{…}` escapes.
- A failing segment renders `✗ <segment>` in the line and explains itself on stderr. It never blanks the whole line, and it never hides the error.
- Editing another program's config: back it up (`<file>.statusmaxxx.bak`), refuse files we cannot rewrite faithfully (JSONC), remember what we replaced, and restore it on uninstall.
- Command agents get a wrapper script path, not a command line, because some spawn it without a shell.
- Logs put dynamic values in `<angle brackets>`. Comments say why.

## Verifying against real agents

Never hand-edit a real agent config in tests or experiments. Use one of these:

- `just try <agent>`, which uses the agent's own override flag (`claude --settings`, `droid --settings`). For Codex, use `codex -c 'tui.status_line=[…]'`.
- `just sandbox <agents…>` for install and uninstall. Every path derives from `HOME`.
- Project-local plugins in a scratch git repo: `.amp/plugins/`, `.pi/extensions/`.

Before trusting a new agent's docs, record a real payload: run it once, then read `~/.cache/statusmaxxx/payloads/<agent>.json`.

| Verified live | From docs only |
|---|---|
| Claude Code, Amp, pi, Droid, Codex item ids | Cursor, Qwen, Copilot (payload undocumented), OpenCode (API only in its repo spec), Gemini item ids |

## Adding an agent

1. Add the variant to `Host`, then extend `ALL`, `id`, `label`, `tier`, `home`, and `note`.
2. Add its entry in its tier module: a `Target` in `command.rs`, a `Shim` in `plugin.rs`, or item ids in `builtin.rs`.
3. Add its global instructions file to `instructions.rs`, if it has one.
4. Add its config dir to the `sandbox` recipe.
5. Verify it live (see above), and move it into the right column of the table.

## Tracking

No tracker. Commit on the current branch (`main`) at a ship boundary. Use a worktree only when I ask. There is no remote yet; once `origin` exists, run plain `git push` after each ship commit. No PRs.

## Release

`cargo-dist` owns the release pipeline, and its config lives in `dist-workspace.toml`. After changing that file, run `dist generate` and commit the regenerated `release.yml`. Never hand-edit `release.yml`. `just release <version>` needs a clean tree and a passing `just check`. The Homebrew formula is attached to each release, but it is not published to a tap.
